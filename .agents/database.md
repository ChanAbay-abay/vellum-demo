# Database (opt-in)

`packages/db` is Drizzle ORM + Postgres (postgres.js). The default landing page doesn't use it. Enable it only when a client needs stored data (inquiries, bookings, accounts).

Targets: Postgres on our VPS, or Supabase.

## Enabling

1. Set `DATABASE_URL` in `packages/env/.env` (and in the host's dashboard).
   - Supabase on Vercel/Cloudflare: use the **transaction pooler** URL (port 6543).
   - VPS Postgres: put PgBouncer in front if traffic is high.
2. Add `"@zo-stack/db": "workspace:*"` to `apps/web/package.json` dependencies and run `vp install`.
3. Define tables in `packages/db/src/schema/` and export them from `schema/index.ts`.
4. Generate a migration: `vp run db:generate`. Review the SQL in `packages/db/migrations/`.
5. Apply it: `vp run db:migrate`. Developers run this themselves. Agents generate migrations but never apply them, and must stop and warn if `DATABASE_URL` isn't a local database.

## Usage

Only inside server functions or server routes:

```ts
import { createDb } from "@zo-stack/db";

const db = createDb();
```

`createDb()` returns a new client each call. Call it per request: Cloudflare Workers can't reuse a connection across requests. `prepare: false` keeps it compatible with transaction poolers.

## Conventions

- Prefer `text().$type<"draft" | "published">()` over native Postgres enums. Validate untrusted values at the boundary.
- `src/schema/auth.schema.ts` is generated by `vp run auth:generate` from the Better Auth config. Don't hand-edit it.
- Keep the main relations in `src/schema/relations.ts` (`defineRelations`); auth relations merge after them in `src/index.ts`.
- There's no local Docker database. Use a local Postgres install or a Supabase dev project for development.
